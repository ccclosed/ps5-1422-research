# 14.22: альтернативные пути добыть образ — recovery, регионы, зеркала, дампы

> Задача: task-16. Дата проверок: 2026-11-11, машина без root, сеть через `socks5h://127.0.0.1:10810`.
> Инструмент: `ps5jb/tools/pup/fetch.py` (list/resolve/verify) — используется в разделах 1 и 2.
> Всё ниже — факты с HTTP-кодом, размером и (где возможно) хешем. Непроверенное помечено `[НЕ ПРОВЕРЕНО]`.

## 0. TL;DR (для лида)

1. **Recovery-образ 14.22 существует и скачивается**: `rec_42ea0e5a…`, **HTTP 200, 1 423 697 408 байт**, ETag-MD5 `ab9e3377583badd0f955c045b6302e77`. Ссылка лежит на **официальной странице Sony** рядом с обычной.
2. **Recovery-образ 14.20 тоже существует**: `rec_549cf0d5…`, **HTTP 200, 1 423 693 312 байт** (найден через зеркало, подтверждён на Sony).
3. **Менее защищённых образов нет**: sys и rec — одинаковый контейнер `SLB2` v3 и одинаковое шифрование; энтропия 1 МиБ в 5–6 точках каждого файла = **8.000 бит/байт** (шифртекст). Отличие только в заголовке (rec = 2 записи в контейнере вместо 1) и размере (+157 606 400 байт).
4. **Регионы и модели ничего не добавляют**: `?dest=us/eu/jp/gb/de/au` дают тот же файл; локали `en-gb/ja-jp/ru-ru/de-de` показывают те же `sys_b0d5818d…`/`rec_42ea0e5a…`; для PS5 Pro/Slim отдельного PUP нет.
5. **Devkit/testkit публично не выложены**: `partners.playstation.net` → 200, но это страница входа (4 514 байт); у единственного крупного зеркала категории только `ps5sys` и `ps5rec`.
6. **Зеркало с полными файлами 14.20/14.22 найдено**: `archive.midnightchannel.net/SonyPS/Firmware/?cat=ps5sys|ps5rec` — прямые ссылки с sha256 в пути, размеры совпадают с Sony, первые 4 КиБ байт-в-байт идентичны.
7. **Публичных дампов с консолей 14.2x нет** (проверено: GitHub-поиск, репозитории-дамперы, archive.org, кодовый поиск) — только инструменты дампинга и исследования 13.60/14.10.

## 1. База: официальный образ и инструмент

```bash
export HTTPS_PROXY=socks5h://127.0.0.1:10810
python3 ps5jb/tools/pup/fetch.py resolve 14.22
# version : 14.22.00.00
# label   : 26.07-14.22.00.00-00.00.00.0.1
# size    : 1266091008
# sha256  : b0d5818d5ce26e2537d1e2febaebd9a3bef1bb1cf8e9898ddf099773706a810b
# url     : http://dus01.ps5.update.playstation.net/update/ps5/official/tJMRE80IbXnE9YuG0jzTXgKEjIMoabr6/image/2026_1027/sys_b0d5818d.../PS5UPDATE.PUP?dest=us
```
`fetch.py resolve 14.20` → `14.20.00.07`, size `1266086912`, sha256 `0f81be6fd890bc04925b3953e0862dfc2ead68edfdc33f31c3c60d0c267f68e4`, каталог `image/2026_1014/`.

Замечания по инструменту:
- `resolve`/`verify` работают; для `download` нужен `HTTPS_PROXY` (urllib не берёт SOCKS из env автоматически только для https — проверено, что с `HTTPS_PROXY=socks5h://…` работает).
- `http://dus01…` и `https://dus01…` ведут себя по-разному: у `dus01` сертификат не совпадает с именем (`curl` без `-k` падает: «no alternative certificate subject name»), а `https://pc.ps5.update.playstation.net/…` — чистый 200. Для проверок ниже использован хост `pc`/официальный https.

## 2. Recovery PUP для 14.20 / 14.22

### 2.1 Откуда берётся ссылка

Официальная страница Sony «PS5 system software» (`https://www.playstation.com/en-us/support/hardware/ps5/system-software/`, **HTTP 200, 162 885 байт**) содержит **две** ссылки с текстами:

```
Download the PS5 console update file below and save it in the "UPDATE" folder. …   ← sys
Download the reinstallation file below and save it in the "UPDATE" folder. …       ← rec
```

фактические URL из её HTML:
```
…/image/2026_1027/sys_b0d5818d5ce26e2537d1e2febaebd9a3bef1bb1cf8e9898ddf099773706a810b/PS5UPDATE.PUP
…/image/2026_1027/rec_42ea0e5aad1361e098837d40157863c4c519f0bbc66eb03c04dbaaf339b063fb/PS5UPDATE.PUP
```
Т.е. **recovery-образ для актуальной прошивки публикуется там же, где обычный**, и его sha256 виден в пути. Это ключ: recovery не «спрятан», просто лежит второй ссылкой.

curl -x socks5h://127.0.0.1:10810 -I "$REC14_22"

# Last-Modified: Fri, 30 Oct 2026 02:30:15 GMT

curl -x socks5h://127.0.0.1:10810 -r 0-4095 -o rec1422-head.bin "$REC14_22"

Итог: recovery 14.22 — **живой официальный файл**, 1.33 ГБ, ETag даёт MD5 (`ab9e3377…`), т.е. целостность можно проверить двумя способами (MD5 из ETag, sha256 из пути).

### 2.3 Recovery 14.20 — найден и подтверждён на Sony

Sony на странице показывает только последнюю версию, поэтому ссылку на 14.20 дало зеркало (раздел 4): sha256 `549cf0d5febeca28eb0716abf086639cb216b1400ead8059de13956d0d302762`. Она **принимается официальным CDN**:
```bash
REC14_20="https://pc.ps5.update.playstation.net/update/ps5/official/tJMRE80IbXnE9YuG0jzTXgKEjIMoabr6/image/2026_1014/rec_549cf0d5febeca28eb0716abf086639cb216b1400ead8059de13956d0d302762/PS5UPDATE.PUP"
curl -x socks5h://127.0.0.1:10810 -I "$REC14_20"
# HTTP/1.1 200 OK
# Content-Length: 1423693312
# ETag: "f2f011c20050ad6543e043f4b938cde4:1792466663.348902"
```
И первые 4 КиБ Sony и зеркала **совпадают побайтно**:
```bash
curl -r 0-4095 -o sony_rec1420.bin "$REC14_20"
curl -r 0-4095 -o mir_rec1420.bin "https://archive.midnightchannel.net/SonyPS/Firmware/download/549cf0d5.../PS5REC_CRC%5B8292CC4E%5D_PS5UPDATE.PUP"
cmp sony_rec1420.bin mir_rec1420.bin && echo IDENTICAL   # IDENTICAL
```
Вывод: **recovery-образ 14.20 доступен и на Sony, и на зеркале**, 1 423 693 312 байт.

### 2.4 Чем recovery отличается от sys (факты из контейнера)

Сравнение первых 4 КиБ `sys_2026_1027` и `rec_2026_1027`:
```bash
cp ps5jb/fw/r64-q-2026_1027.bin /tmp/sys1422-head.bin       # первые 64 МиБ sys 14.22
cmp -l sys1422-head.bin rec1422-head.bin | wc -l            # 88 байт различий в первых 4 КиБ
python3 - <<'EOF'
import struct
for tag,f in [("sys","/tmp/sys1422-head.bin"),("rec","/tmp/rec1422-head.bin")]:
    d=open(f,"rb").read(0x40)
    print(tag,"magic",d[:4],"@0x04",struct.unpack_from("<I",d,4)[0],
          "@0x08",hex(struct.unpack_from("<I",d,8)[0]),"@0x0c",struct.unpack_from("<I",d,12)[0],
          "@0x10",struct.unpack_from("<Q",d,16)[0],"@0x20",hex(struct.unpack_from("<Q",d,0x20)[0]),
          "name",d[0x30:0x40].split(b"\0")[0])
EOF
# sys magic b'SLB2' @0x04 3 @0x08 0x10000   @0x0c 1 @0x10 2472834 @0x20 0x4b76fe7d00000002 name b'PS5UPDATE1.PUP'
# rec magic b'SLB2' @0x04 3 @0x08 0x1010000 @0x0c 2 @0x10 2780659 @0x20 0x4b76fe7d00000002 name b'PS5UPDATE1.PUP'
```

| Поле | sys 14.22 | rec 14.22 | Смысл |
|---|---|---|---|
| magic/version | `SLB2`, 3 | `SLB2`, 3 | тот же контейнер и формат |
| `0x08` | `0x00010000` | `0x01010000` | у rec выставлен бит `0x01000000` |
| `0x0c` | 1 | 2 | **число записей/секций: 1 vs 2** |
| `0x10` | 2 472 834 | 2 780 659 | размер таблицы/дескриптора |
| `0x20` | `0x4b76fe7d00000002` | то же | один и тот же серийник сборки |
| имя внутри | `PS5UPDATE1.PUP` | `PS5UPDATE1.PUP` | одинаковое |
| размер файла | 1 266 091 008 | **1 423 697 408** | +157 606 400 байт |

Практический вывод: recovery — это **тот же зашифрованный контейнер с дополнительной секцией** (2 записи против 1), а не «распакованный/сервисный» образ.

### 2.5 «Нет ли менее защищённого»: энтропия по точкам

```bash
# 1 МиБ Range-запросов в 5–6 точках sys и rec 14.22, считаем энтропию
# sys off=0x0/0x100000/0x4000000/0x20000000/0x4b000000 → entropy=8.000 во всех точках
# rec off=0x0/0x100000/0x4000000/0x20000000/0x4b000000/0x54000000 → entropy=8.000 во всех точках
# хвост rec (офсет 1 423 000 000, окно 600 000 байт): entropy tail: 8.0
strings -a -n 8 rec_tail.bin   # только случайные байты, читаемых строк нет
```
**Вывод: recovery-образ не менее защищён** — тот же шифр (энтропия 8.000 по всему файлу, включая хвост), никаких открытых участков не видно. Никаких «сервисных» ключей или plaintext-заголовков в образе не обнаружено.

### 3.1 `dest=` не меняет файл

for dest in us eu jp gb de au; do curl -x socks5h://127.0.0.1:10810 -I -o /dev/null -w "dest=$dest http=%{http_code} clen=%header{content-length}\n" "$U?dest=$dest"; done

# dest=eu http=200 clen=1266091008
# dest=jp http=200 clen=1266091008   (gb/de/au — то же)

## 7. Что это значит для нас

1. **Recovery-образы 14.20 и 14.22 доступны публично** (официально и с зеркала) — значит у нас есть *оба* контейнера, и в отличие от обычного sys в recovery-контейнере **2 секции вместо 1**. Это дополнительный материал для статического анализа: если когда-нибудь появится расшифровка/утечка ключей, recovery может содержать сервисные компоненты, которых нет в sys.
2. **Меньше защиты нет**: 8.000 бит/байт энтропии в 6 точках rec (включая хвост) — рассчитывать на «сервисный образ с открытыми ключами» нельзя.
3. **Для 14.2x у нас нет ничего, кроме официальных PUP**: ни дампов, ни расшифрованных частей. Поэтому стратегия «добыть образ» исчерпана: остаётся ждать (а) публичного дампа с консоли, (б) утечки ключей, (в) расшифровки офлайн.
4. Следующий шаг, который имеет смысл: скачать **recovery 14.22 целиком** (1.42 ГБ) в `ps5jb/fw/` и зафиксировать sha256/MD5, чтобы в будущем сравнивать с любой утечкой; плюс сравнить структуры sys/rec на известных офсетах (границы секций в SLB2-заголовке).

Скачивание выполнялось Range-запросами по 16 МиБ (85 кусков) с докачкой — прямая загрузка целого файла через SOCKS-прокси рвётся (`SSL unexpected eof`). Хеши обоих файлов совпали с независимо скачанными копиями и с метаданными Sony — файлы аутентичны.

### 8.2 Формат SLB2: заголовок расшифрован (0x400 байт, plaintext)

| Смещение | Тип | sys 14.22 | rec 14.22 | rec 14.20 | Смысл |
|---|---|---|---|---|---|
| 0x00 | char[4] | `SLB2` | `SLB2` | `SLB2` | магия |
| 0x04 | u32 | 3 | 3 | 3 | версия контейнера |
| 0x0A | u8 | 1 | 1 | 1 | флаг (постоянный 1) |
| 0x0B | u8 | **0** | **1** | **1** | **флаг recovery** |
| 0x0C | u16 | 1 | 2 | 2 | число записей |
| 0x10 | u64 | 2 472 834 | 2 780 659 | 2 780 651 | **размер файла в 512-байтных секторах** (×512 = точный размер) |
| 0x20 + n·0x30 | — | запись 1 | записи 1–2 | записи 1–2 | см. ниже |

Запись (0x30 байт): `u32 offset_sectors`, `u32 size_bytes`, `char name[0x20]`. Данные записи лежат по `offset_sectors*512`, занимают `ceil(size_bytes/512)*512` байт.

- sys 14.22: `(2, 1 266 089 597, "PS5UPDATE1.PUP")` → начало `0x400`, хранится `1 266 089 984` байт (1024 + это = 1 266 091 008 ✓).
- rec 14.22: `(2, 1 266 089 597, "PS5UPDATE1.PUP")` + `(2 472 834, 157 606 077, "PS5UPDATE2.PUP")` → второй образ начинается с `2 472 834*512 = 0x4B770400`, хранится `157 606 400` байт.
- rec 14.20: `(2, 1 266 085 469, "PS5UPDATE1.PUP")` + `(2 472 826, 157 606 077, "PS5UPDATE2.PUP")` → второй образ с `0x4B76F400`.

### 8.3 Rec = байт-в-байт sys + один дополнительный образ

Проверено хешами сегментов:
```text
rec22[0x400 : 0x4B770400] sha256[0:24] = 05a2a3e78c438703c0f9e782   ← совпадает с телом sys 14.22
rec20[0x400 : 0x4B76F400] sha256[0:24] = 98a5655b1628955e7745ae00   ← совпадает с телом sys 14.20
rec22[0x4B770400 : конец] sha256[0:24] = 82117f4992cfd26e6a46b6a7   (157 606 400 байт)
rec20[0x4B76F400 : конец] sha256[0:24] = d79d0b1cba581f95ca71bbe7   (157 606 400 байт)
```
То есть recovery-образ 14.22 **не переупаковывает систему**: первые 1.266 ГБ — это ровно тот же sys-образ (совпадение по хешу), а в конце добавлены 157.6 МБ второго образа. Это же верно для 14.20.

### 8.4 Что за второй образ и есть ли в нём незашифрованное

- Начало второго образа (`0x4B770400`): `54 14 f5 ee 10 01 01 32 04 00 00 00 40 02 a0 05 …` — магия `0x5414F5EE` (fSELF), далее 12 байт полей, из них `u32 0x05A00240 = 94 371 392`.
- Первый образ начинается так же (`0x400`): `54 14 f5 ee 10 01 01 32 04 00 00 00 B0 05 E0 0D …`, `u32 0x0DE005B0 = 232 784 304`.
- Энтропия (ключевой ответ): в заголовке `SLB2` — 1.64/0/2.17/1.15 бит/байт по окнам 256 байт, доля нулей 75–100 % → **заголовок открытый**. Сразу после `0x400` — 7.95–8.00 бит/байт в окнах 4 КиБ/64 КиБ, нулей 0.3–0.5 % → **тело зашифровано/сжато**. Ни в sys, ни в rec нет ни одного 1-МиБ окна с долей нулей >1 %, и нет читаемых строк, кроме двух имён в заголовке.
- **Вывод: recovery не содержит открытых таблиц/метаданных сверх 1 КБ заголовка.** Он даёт ровно один дополнительный зашифрованный образ `PS5UPDATE2.PUP` (157.6 МБ), происхождение которого определяется только после расшифровки.

### 8.5 Что изменилось между rec 14.20 и rec 14.22

| Параметр | rec 14.20 | rec 14.22 | Δ |
|---|---|---|---|
| Размер файла | 1 423 693 312 | 1 423 697 408 | +4 096 байт (8 секторов) |
| `PS5UPDATE1.PUP` (size) | 1 266 085 469 | 1 266 089 597 | +4 128 байт |
| `PS5UPDATE1.PUP` (sha256) | 98a5655b… ≠ | 05a2a3e7… | содержимое изменено (совпадает с соответствующим sys) |
| `PS5UPDATE2.PUP` (size) | 157 606 077 | 157 606 077 | 0 (размер тот же) |
| `PS5UPDATE2.PUP` (sha256) | d79d0b1c… | 82117f49… | **содержимое изменилось** |

Практический вывод: recovery-«добавка» пересобирается вместе с прошивкой (размер стабилен, содержимое — нет), т.е. это не статический служебный раздел, а версионно-зависимый образ.
