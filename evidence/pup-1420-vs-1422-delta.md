# 14.20 → 14.22: что именно изменено (без ключа)

Статус: task-11. Дата: 2026-11-11. Машина Linux, без root; консоли/ключей нет.
Пара: `fw/PS5UPDATE-sys-2026_1014.PUP` (14.20, 1 266 086 912 Б, sha256 `0f81be6f…`) → `fw/PS5UPDATE-sys-2026_1027.PUP` (14.22, 1 266 091 008 Б, sha256 `b0d5818d…`). Целостность обоих подтверждена ранее (`fetch.py verify` rc=0).
Инструмент: `tools/pup/delta1422.py` (точные сравнения numpy, без эвристик). Все числа ниже — из прогонов, сохранённых в `tools/pup/output/`.

## 0. TL;DR — 8 пунктов

1. **14.22 — полный образ, а не дельта-патч на уровне контейнера**: SLB2 с одной записью `PS5UPDATE1.PUP`, нет записей/ссылок на базовую версию, нет plaintext-маркеров `14.20`/`base_version`/`delta`/`bsdiff`/`patch`/`zchunk` во всём файле (0 вхождений), размер файла полный (~1.266 ГБ).
2. Разница размеров: файл **+4 096 Б** (=8 × 512 = ровно одна 4 КиБ-страница), образ (запись SLB2) **+4 128 Б**, паддинг образа **−32 Б** (419 → 387), `block_count` **+8**.
3. **Области `header_size=1456` и `metadata_size=3552` — шифротекст без читаемых полей**: энтропия 7.87–7.95; все 16-байтные блоки уникальны (90/90 и 222/222); совпадение с другой версией 0.42% и 0.34% ≈ случайные 1/256 = 0.3906%; равных 16-байтных блоков между версиями — **0**.
4. Два 32-байтных поля `0x200`/`0x3E0` изменились, но не опознаны: ни один из 10 кандидатов SHA-256 (файл, образ, образ+паддинг, срезы заголовка, header/metadata-области) не совпал; ранее отвергнуты и варианты с обнулёнными полями и MD5.
5. **Постраничная карта**: равных 512-байтных секторов **0 / 2 472 826**; равных 4 КиБ-страниц **0 / 309 103**; равных 16-байтных блоков **59 — все внутри структурной зоны [0, 0x410)**, вне её — 0 (нет ни одного совпадающего ряда ≥8 байт).
6. Каждое 1 МиБ-окно файла различается на **99.52–99.63%** (среднее 99.6095%); окон, где хотя бы одна страница совпадает, — **0 из 1208**. Совпадающие байты по всему файлу — **0.3905%**, т.е. ровно случайный уровень 1/256.
7. Тест на «вставку/сдвиг»: при сдвиге от −256 до +256 секторов (включая ±8 секторов = ±4096 Б) — **0 совпадающих секторов**; общих секторов между файлами на любых смещениях — **0**; повторяющихся секторов внутри файла — **0**. Значит нет ни дельта-структуры с сохранением данных, ни позиционно-детерминированного шифрования.
8. **Вывод по локализации: НЕТ.** По контейнеру нельзя сказать, какая подсистема изменена. Видны только факты уровня упаковки: «тот же формат, +1 страница, другие дайджесты». Для ответа «что именно исправлено» нужен расшифрованный образ (ключ консоли/дамп), иначе это невозможно в принципе.

## 1. Метод

```bash
cd /home/oleg/Документы/ps5semulator/ps5jb
python3 tools/pup/delta1422.py fw/PS5UPDATE-sys-2026_1014.PUP fw/PS5UPDATE-sys-2026_1027.PUP \
  --label-a 14.20 --label-b 14.22 --map-out tools/pup/output/diffmap-1420-1422.txt
# baseline для контекста:
python3 tools/pup/delta1422.py fw/PS5UPDATE-sys-2026_0928.PUP fw/PS5UPDATE-sys-2026_1014.PUP \
  --label-a 14.10 --label-b 14.20 --max-shift 32
```

Что делает `delta1422.py` (всё — точные побайтовые сравнения через numpy, не выборки):

- разбирает SLB2-заголовок и запись, сравнивает поля;
- сканирует **весь файл** на точные ASCII-маркеры (версии, `base_version`, `delta`, `bsdiff`, `zchunk`, `patch`, `kernel`, …);
- разбирает области `header_area = [0x410, 0x9B0)` (1440 Б) и `metadata_area = [0x9B0, 0x1790)` (3552 Б): энтропия, нули, уникальность 16-байтных блоков, энтропия по блокам, печатные ряды, повторяемость между версиями;
- по всему общему объёму считает: равные байты, равные 16-байтные блоки, равные 4 КиБ-страницы, разницу по окнам 1 МиБ; пишет карту;
- строит 64-битные «дайджесты» секторов 512 Б (XOR-свёртка 64 слов; равные сектора всегда дают равный дайджест, ложное совпадение ~2⁻⁶⁴) и проверяет: совпадения при сдвигах −256…+256 секторов, общие сектора между файлами, повторы внутри файла;
- отдельно: длины общего префикса/суффикса, размерная дельта, тесты «дайджест = SHA-256 от читаемой области».

Сырые выводы: `output/delta-1420-1422.txt` (основной), `output/delta-1410-1420-baseline.txt` (контекст), `output/diffmap-1420-1422.txt` (карта), `output/delta-digests.txt` (расширенные тесты дайджестов), `output/equal-runs-1420-1422.txt` (ряды равных байт).

## 3. Области `header_size=1456` / `metadata_size=3552`

Раскладка: PUP-фрагмент начинается на 0x400; открыты 16 байт `[0x400,0x410)`; `header_area = [0x410,0x9B0)` = 1440 Б; `metadata_area = [0x9B0,0x1790)` = 3552 Б.

| метрика | 14.20 header_area | 14.22 header_area | 14.20 metadata_area | 14.22 metadata_area |
|---|---|---|---|---|
| длина, Б | 1440 | 1440 | 3552 | 3552 |
| энтропия, бит/Б | 7.8693 | 7.8826 | 7.9448 | 7.9502 |
| нулевых байт | 3 | 6 | 10 | 13 |
| различных значений байт | 256 | 255 | 256 | 256 |
| уникальных 16-Б блоков | 90 / 90 | 90 / 90 | 222 / 222 | 222 / 222 |
| энтропия 16-Б блока (min/mean/max) | 3.75 / 3.9431 / 4.0 | 3.7028 / 3.9345 / 4.0 | 3.625 / 3.9487 / 4.0 | 3.7028 / 3.939 / 4.0 |
| печатные ряды ≥4 символов | случайные 4-символьные обрывки (`BwxD`, `0ut?`, …) | аналогично | аналогично | аналогично |

Попарное сравнение «14.20 vs 14.22» в тех же областях:

| область | equal_bytes | equal_16B_blocks | ожидание при 1/256 |
|---|---|---|---|
| header_area | 6 / 1440 = **0.42%** | **0 / 90** | 0.3906% |
| metadata_area | 12 / 3552 = **0.34%** | **0 / 222** | 0.3906% |

Нулей 3–13, различных байт 256, энтропия 16-байтных блоков 3.6–4.0 бита (=16 разных байт в блоке), совпадение с другой версией на уровне случайного — **все признаки равномерного шифротекста**. Печатные 4-символьные «ряды» — статистический шум случайных байт, а не поля.

**Вывод по §3: читаемых полей в этих областях нет.** Единственные читаемые поля внутреннего PUP — 16 байт `[0x400,0x410)`, и они у 14.20/14.22 **идентичны** (`5414f5ee 1001 0132 0400 0000 b005 e00d`). Изменения в этих областях есть (шифротекст другой), но что в них — не видно.

## 6. Ответ: можно ли локализовать изменённую подсистему?

**Нет.** Обоснование — все измерения выше:

1. метаданные, которые могли бы указать на компонент (таблица сегментов, metadata-область, имена, хэши), — шифротекст; читаемых полей в этих областях 0 (§3);
2. нет ни одного совпадающего сектора/страницы/16-байтного блока вне структурной зоны, поэтому «где изменение» определить не по чему: различие распределено по всем 1208 окнам на 99.6% (§5);
3. нет дельта-структуры/ссылок на базу (§2), нет сохранения данных при сдвигах на ±4096 Б (§5.4) — то есть даже «место вставки» одной страницы не определяется;
4. два 32-байтных поля-дайджеста изменились, но не расшифровываются и не сопоставимы ни с каким читаемым срезом (§4).

**Частично** можно утверждать только свойства упаковки: формат контейнера и PUP-заголовка не менялся; размер образа вырос на 4 128 Б; дайджесты иные; образ перешифрован целиком. Это не даёт ответа «какая подсистема».

**Что нужно, чтобы стало возможно:**
1. **Расшифрованный образ** — ключ/драйвер `/dev/pup_update0` на консоли (по данным ранней разведки репозитория, публичной ПК-расшифровки нет) или дамп расшифрованного PUP с консоли;
2. после этого — разбор таблицы сегментов (гипотеза: 44 сегмента, PS4-формула) и сегментный дифф: какие образы/модули изменились; поиск строк версий, ELF/ядровых образов, bindiff;
3. альтернатива без ключа — только косвенные данные вне контейнера (официальные патчноуты/CVE, см. `recon/cve-and-notes.md`, `recon/1422-status.md`), но они не доказывают содержимое данного PUP.
