# Дампы PS5 и их эпоха: requiredSystemSoftwareVersion → FW/SDK (в работе)

Задача: найти среди публичных дампов PS5 такие, чьи `sce_module/*.prx` относятся к
**14.x-эпохе**. Дата загрузки на хостинг — не показатель: Code Violet загружен 2026-11-10,
а собран под **SDK 11.00 / FW 12.70**. Поэтому фильтр — поле
`requiredSystemSoftwareVersion` в `sce_sys/param.json` внутри дампа.

## 0. Правило декодирования (из `recon/module-era-decoding.md`, декодер KytyPS5)

`requiredSystemSoftwareVersion` = `0x` + **6 десятичных цифр** `MMmmpp` + 10 hex-цифр.
Пример: `0x1422000000000000` → FW **14.22**. То же правило — для `sdkVersion`.

Калибровка команды: **Code Violet PPSA26528 v01.028**: `0x1270…` → FW 12.70, sdk `0x1100…`
→ SDK 11.00 (старьё, не наше). Cyberpunk 2077 PPSA04029 v02.120 — модули с build-путём
`W:/Build/J01625764`, эпоха ~8.x.

## 1. Инструменты (в `fw/game-modules/tools/`)

| инструмент | что делает |
|---|---|
| `exfat_param.py` | читает `sce_sys/param.json` из **.exfat**-образа по HTTP Range (SOCKS5 keep-alive + предзагрузка slab) или локально |
| `extract_ffpfsc.py` + `ffpfsc_remote.py` | читает внутренний exFAT из **.ffpfsc**-дампа по Range (PFSC-контейнер, 64-КиБ блоки) |
| `module_meta.py` | метаданные PRX: sha256, PT_SCE_COMMENT (build-путь), версии, размер |
| `exfat_fast.py` | общий Range-клиент (SOCKS5 + TLS + keep-alive) для exFAT |

Важные грабли (исправлено): каталог exFAT надо читать по его DataLength, иначе при флаге
`NoFatChain` обход уходит в бесконечное чтение соседних кластеров (и это выглядело как
«зависание» на 5–10 минут). Латентность одного Range к archive.org через прокси ~5 с,
поэтому дешевле один slab 8 МБ, чем 20 запросов по 64 КиБ.

```bash

        --size 1354760192 --slab 8388608 --json
```

## 4. Выводы (обновляется)

* Метод работает: `param.json` читается из 1.3-ГБ образа за **6 Range-запросов** и 35 с,
  образ целиком не качается.
* Первые же проверки подтверждают главный тезис: **дата загрузки ≠ эпоха**. Игра,
  загруженная 2026-10-12, собрана под FW 10.01 / SDK 9.00.
* Наблюдение по 6 дампам загрузки авг–окт 2026: их FW = 6.50 / 10.01 / 11.20 / 12.20 / 12.60 — **ни одного 13.x/14.x**. Самые свежие (сентябрь–октябрь 2026) сидят на 12.20–12.60, то есть дампы публикуются с отставанием эпохи, а не с прошивкой загрузки.
* Задача — перебрать все дампы с датой ≥ 2026-06 (и отдельно все `.ffpfsc`), отсортировать
  по FW и на FW ≥ 13.x достать модули (build-путь `W:/Build/J…`, размер `libc.prx`).
