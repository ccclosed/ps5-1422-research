# Дифф PUP 14.10 / 14.20 / 14.22 — структура контейнера SLB2

Статус: task-8 выполнен. Дата: 2026-11-11. Машина: Linux, без root, консоли нет.
Использовано: только официальные PUP Sony (скачаны с `dus01.ps5.update.playstation.net` прямым HTTP, HEAD 200) и локальный разбор. Ключи/расшифровка не применялись.
Артефакты: `tools/pup/parse.py` (1207 строк, `--selftest` PASSED), `tools/pup/output/parse-all.txt` (полный сравнительный вывод), `tools/pup/output/*.txt` (сырые прогоны).

## 0. TL;DR (проверено, не гипотезы)

1. Все три PUP — **SLB2-контейнер** (`SLB2`, version=3, flags=0x00010000, file_count=1) c **одной** записью `PS5UPDATE1.PUP` на смещении 1024 (`block_offset=2`). Таблица записей SLB2 **читается полностью**.
2. Внутри — **один зашифрованный образ** (PS5 PUP, magic `0xEEF51454`). Открытыми в нём являются только **первые 16 байт** заголовка; всё дальше (таблица сегментов, метаданные, полезная нагрузка) — шифротекст.
3. Эти 16 байт **побайтово идентичны у всех трёх версий**: `5414f5ee 1001 0132 0400 0000 b005 e00d` (version=272, u16@6=12801, u16@8=4, flags=0, header_size=0x5B0=1456, metadata_size=0xDE0=3552). То есть формат контейнера и размеры областей заголовка/сегментов между 14.10 и 14.22 не менялись (само число сегментов n=44 — гипотеза, см. §3.2).
4. Таблица сегментов **не читается** (flags bit0 = 0 → шифрование). Гипотеза по PS4-формуле: `header_size = 0x20 + n*0x20 + 0x10` → **n=44 сегмента**, `metadata_size = 0x20 + n*0x50` → 44 записи метаданных; одинаково для всех трёх версий. Это **гипотеза**: байты области зашифрованы, поэтому пробы раскладок не могут её подтвердить (энтропия 7.86–7.89, структурные метрики нулевые — см. §3.3).
5. Реально сравнимые величины: размеры (файл/образ/паддинг), `block_count`, поля заголовка SLB2, 16-байтовый plaintext-префикс PUP, два 32-байтовых поля-дайджеста (0x200 и 0x3E0), энтропия, распределение вхождений сигнатур.
6. Размеры: 14.10 → 1 261 408 256; 14.20 → 1 266 086 912 (+4 678 656 = +9 138 блоков по 512); 14.22 → 1 266 091 008 (+4 096 = +8 блоков). Паддинг до 512: 451 / 419 / 387 байт (уменьшается на 32 на каждом шаге).
7. В шифротексте **ноль совпадающих 16-байтных блоков** между версиями (32 пробы × 64 КиБ на одинаковых смещениях; единственное совпадение — plaintext-заголовок на 0x400). Образ перешифровывается целиком при каждом релизе.
8. Наблюдаемые «магии» внутри шифротекста (GZIP=65/77/75, ZIP=0/1/0, zlib≈19 тыс., второй SLB2/PS5_PUP) **точно соответствуют случайному распределению** для 1.26 ГБ — никаких видимых вложенных структур (ELF/PKG/ZIP/…) нет.
9. Для диффа **ядра** этого недостаточно: нужен расшифрованный образ (ключ у консоли, не в пакете), иначе видно только «контейнер + размеры». Это главный честный вывод.

## 3. Внутренний PUP: что видно и что зашифровано

### 3.1 Открытый 16-байтовый префикс (0x400–0x410) — идентичен у всех трёх

```
5414f5ee 1001 0132 0400 0000 b005 e00d
```
| смещение | поле | значение (все три версии) |
|---|---|---|
| 0x400 | magic | `0xEEF51454` (PS5 PUP) |
| 0x404 | version | 272 (0x0110) |
| 0x406 | u16 | 12801 (0x3201) |
| 0x408 | u16 | 4 |
| 0x40A | flags | 0x0000 → **bit0 (plaintext) = 0 ⇒ заголовок шифрован** |
| 0x40C | header_size | 1456 (0x5B0) |
| 0x40E | metadata_size | 3552 (0xDE0) |

Побайтовое сравнение 0x000–0x440 (`output/header-fields-3ver.txt`) даёт 5 смысловых групп различий: `block_count` (0x010), `size` записи (0x024), дайджест №1 (0x200–0x21F), дайджест №2 (0x3E0–0x3FF) и шифротекст с 0x410. Всего 117 различающихся байт для пар с 14.10 и 115 для 14.20/14.22 (короче на один байт `block_count` и один байт `size`). Всё остальное, включая весь открытый префикс PUP, **побайтово одинаково**.

### 3.2 Гипотезы о числе сегментов (не факты)

`header_size = 1456 = 0x20 + 44×0x20 + 0x10` — точное совпадение с PS4-формулой, откуда **n=44** (44 записи по 0x20). `metadata_size = 3552 = 0x20 + 44×0x50` — 44 записи метаданных по 0x50. Одинаково для всех трёх версий. PS5-формула публично не подтверждена, поэтому статус — гипотеза.

### 3.3 Пробы раскладок таблицы (устойчивый разбор: пробуем — отвергаем)

`parse.py` пробует 5 раскладок: `0x20+n*0x20+0x10` (PS4), `0x20+n*0x20`, `0x20+n*0x20+0x20`, `0x20+n*0x30+0x10`, `n*0x20+0x10` от начала файла. Для каждой — читает регион, считает энтропию и структурные метрики (доля смещений в границах фрагмента, монотонность, выравнивание, правдоподобность сжатых размеров; «credible» = энтропия<7.0 и все доли>0.95).

- раскладки `0x20+n*0x20`, `+0x20`, `0x30` **не подходят по арифметике** header_size (отвергнуты);
- раскладки, подходящие арифметически (`n=44`, и `n=45` от начала файла), прочитаны, но **не credible**: энтропия 7.8643/7.8696/7.8809 и 7.8669/7.8694/7.8858; `offset_in_range_fraction=0.0`, `plausible_compressed_size_fraction=0.0` во всех случаях.

**Вывод:** таблица сегментов зашифрована; честный парсер обязан сказать «не читается», а не выдать мусор за записи. Именно так и сделано — см. `--compare` в `output/parse-all.txt`.

Устойчивость проверена на повреждённых входах: обрезанный до 4 МиБ файл даёт предупреждения (`file[0] ... exceeds file size`, `block_count*512 != file size`) и печатает всё, что читается, без падения (rc=0); 2 КиБ случайных данных дают `WARNING: unrecognised magic 0xB4E41AD8`, rc=0 (команды: `head -c 4194304 fw/PS5UPDATE-sys-2026_1027.PUP > /tmp/pup-trunc-4mb.bin` и т.п.).

## 5. Что в зашифрованном контейнере **не читается** (честный список)

- **Таблица сегментов PUP** (44 потенциальные записи): id/тип, смещения, сжатые/несжатые размеры, флаги (encrypted/signed/compressed/blocks/digests), размер блока — всё шифротекст. Публичного ключа на ПК нет.
- **Область метаданных** (3552 Б) — шифротекст (энтропия 7.94–7.95).
- **Полезная нагрузка** — шифротекст (энтропия 7.9998): ни имён внутренних образов (kernel, SceSysCore, etc.), ни их границ и размеров.
- **Содержимое обновления**: какие компоненты/модули изменены, какие патчи безопасности (CVE) закрыты — по PUP без ключа определить нельзя.
- **Подписи/хэши**: два 32-байтовых поля (0x200, 0x3E0) видны, но не опознаны (проверенные гипотезы о SHA-256 отвергнуты).
- **Ключи**: в пакете нет ничего, что позволило бы расшифровать образ на ПК; по данным ранней разведки этого репозитория (`recon/pup-format.md`, docstring `parse.py`), публичные инструменты (`zecoxao/ps5-pup-decrypt`, `idc/ps4-pup_decrypt`) передают буферы драйверу `/dev/pup_update0`, т.е. расшифровка происходит **на консоли**. В рамках task-8 это не перепроверялось — помечено как «по данным ранней разведки».

Отдельно: утверждение «внутри контейнера один зашифрованный образ» — **подтверждено** (одна запись `PS5UPDATE1.PUP`, внутри один PUP-фрагмент, дальше шифротекст).

## 6. Что это значит для диффа ядра

1. **Диффа ядра здесь нет и быть не может.** Мы сравнили контейнеры, а не код: видны только метаданные SLB2 и 16-байтовый префикс PUP. Ядро (как и любой внутренний образ) лежит внутри шифротекста; ни имён, ни границ сегментов не видно.
2. Всё, что можно утверждать по диффу: (а) формат контейнера и число сегментов (гипотеза n=44) между 14.10 и 14.22 не менялись; (б) образ 14.22 больше 14.20 всего на 4 128 байт, а 14.20 больше 14.10 на 4 678 688 байт — это оценка **объёма изменений**, а не их содержания; (в) шифротекст перешифровывается целиком, поэтому побайтовое наложение версий бессмысленно.
3. Чтобы получить настоящий дифф ядра, нужен **расшифрованный образ**. Пути: (i) дамп/расшифровка на консоли с рабочим эксплойтом (сейчас для 14.2x публично нет kernel R/W — по данным ветки recon); (ii) утечка расшифрованного PUP/ключа; (iii) сравнение дампов ядра с консолей разных версий. Без одного из этих пунктов любой «дифф прошивок» на ПК останется структурным.
4. Что станет возможным после расшифровки: разобрать таблицу 44 сегментов, выделить образы, найти ядро (по PS4-опыту у PUP есть сегменты с id/типами; для PS5 это предстоит подтвердить) и только тогда делать bindiff/поиск смещений (см. `recon/no-console-methods.md`).

## 7. Воспроизведение (команды и куда пишется вывод)

```bash
cd /home/oleg/Документы/ps5semulator/ps5jb
# 1. метаданные и URL
python3 tools/pup/fetch.py resolve 14.10   # -> output/resolve.txt
python3 tools/pup/fetch.py resolve 14.20
python3 tools/pup/fetch.py resolve 14.22
# 2. скачивание (напрямую с Sony, HEAD 200; файлы в fw/)
curl -L -C - -o fw/PS5UPDATE-sys-2026_0928.PUP "<URL 14.10>"
curl -L -C - -o fw/PS5UPDATE-sys-2026_1014.PUP "<URL 14.20>"
# 3. проверка целостности
python3 tools/pup/fetch.py verify fw/PS5UPDATE-sys-2026_0928.PUP 14.10  # OK
python3 tools/pup/fetch.py verify fw/PS5UPDATE-sys-2026_1014.PUP 14.20  # OK
python3 tools/pup/fetch.py verify fw/PS5UPDATE-sys-2026_1027.PUP 14.22  # OK
# 4. разбор и сравнение (главный артефакт)
python3 tools/pup/parse.py --selftest --out tools/pup/output/selftest.out   # PASSED
python3 tools/pup/parse.py --compare --labels 14.10,14.20,14.22 \
  fw/PS5UPDATE-sys-2026_0928.PUP fw/PS5UPDATE-sys-2026_1014.PUP fw/PS5UPDATE-sys-2026_1027.PUP \
  | tee tools/pup/output/parse-all.txt
# 5. вспомогательные замеры (скрипты-однострочники, вывод сохранён)
#    output/header-fields-3ver.txt  - поля заголовков и диапазоны различий 0x000-0x440
#    output/ciphertext-stats.txt    - энтропия, совпадение блоков, дельты размеров
#    output/misc-probes.txt         - поиск совпавшего блока, гипотезы о 0x200/0x3E0
#    output/magic-offsets.txt       - смещения всех вхождений SLB2/PS5_PUP/ZIP
#    output/tail-and-entry.txt      - запись SLB2 и хвостовой паддинг
#    output/head-3urls.txt          - HEAD официальных URL (Last-Modified)
```

## 8. Проверено / не проверено

| утверждение | статус |
|---|---|
| все три PUP — SLB2 с одной записью `PS5UPDATE1.PUP` @1024 | проверено (`parse.py --compare`) |
| размеры/sha256 совпадают с официальными метаданными | проверено (`fetch.py verify`, rc=0) |
| открытые 16 байт PUP-заголовка идентичны во всех трёх | проверено (побайтовое сравнение) |
| таблица сегментов зашифрована, 5 раскладок отвергнуты | проверено (пробы + метрики) |
| n=44 сегмента и 44 записи метаданных | **гипотеза** (PS4-формула) |
| шифротекст не содержит совпадающих 16-байтных блоков | проверено (32×64 КиБ на парах) |
| «магии» внутри — случайный шум | проверено (совпадение с теор. ожиданием) |
| 0x200/0x3E0 — не SHA-256 от очевидных срезов | проверено (9 кандидатов отвергнуты) |
| ключ только на консоли, ПК-расшифровки нет | по данным ранней разведки репозитория, здесь не перепроверялось |
| что изменилось в ядре/компонентах между версиями | **неизвестно** — требуется расшифрованный образ |
