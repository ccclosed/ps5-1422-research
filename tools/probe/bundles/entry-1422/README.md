# entry-1422 — bundle проб для консоли (PS5 14.22, WebKit entry)

Цель: за один заход на консоли получить ответ на два вопроса:
1. **Закрыт ли в 14.22 вход через реентерабельный Canvas2D `getContext()`**
   (CVE-2026-43720 / WebKit bug 313175) — страница `p1`.
2. **Какой ветке WebKit/Safari соответствует движок 14.22** — `p2` (нужно, чтобы понять,
   ребейзила ли Sony движок; на 14.10 публичный прогон дал полосу Safari 17.0–17.3).

Основание и даты — в `../../../../recon/webkit-1422-verdict.md` (§2, §3, §5).

## Файлы

| Файл | Что это | Безопасность |
|---|---|---|
| `index.html` | хаб, проверка, что стенд живой | безопасно |
| `p1-canvas-reentry.html` | оракул `FIXED / VULNERABLE / UNKNOWN` (same-type 2d→2d + cross-type bitmaprenderer) | не роняет процесс |
| `p2-engine-fingerprint.html` | полоса Safari по 32 API (1:1 с публичным p162) | безопасно |
| `p3-crash-oracle.html` | crash-oracle: чтение свойства освобождённого контекста | **может уронить WebProcess; только с `?armed=1` и только после `p1=VULNERABLE`** |
| `diag-dictionary-getters.html` | вспомогательная: какие члены IDL-словаря `getContext` реально читает движок (alpha в 2d не читается) | безопасно |
| `run.sh` | поднимает HTTPS-сервер проекта с этим каталогом | — |
| `run_local.py` | локальный прогон страницы в WebKitGTK (только для проверки стенда на ПК) | — |

## Как запустить

На ПК (сервер; нужен тот же, что отдаёт страницы консоли):

```bash
cd ps5jb/tools/probe/bundles/entry-1422
./run.sh                 # https://0.0.0.0:8443/  (сертификат и логи — tools/probe/)
# PORT=9443 ./run.sh     # другой порт
```

Логи: `ps5jb/tools/probe/logs/requests.jsonl` (все запросы + UA) и
`ps5jb/tools/probe/logs/beacons.jsonl` (JSON от страниц). Сертификат самоподписанный —
на консоли его надо принять (или доставить страницы через тот же механизм, которым в
проекте уже пользуются для проб: User's Guide + локальный сервер).

На консоли: открыть `https://<IP-ПК>:8443/` (хаб) → `p1` → `p2`; `p3` — только если `p1`
сказала `VULNERABLE` и только с `?armed=1`.

## Что смотреть в логе (beacons.jsonl)

Каждая страница шлёт JSON на `POST /beacon`. Ищите по тегам:

| Тег | Значение | Вывод |
|---|---|---|
| `HUB-OPEN` | хаб открылся, движок дошёл до JS | стенд работает |
| `P1-RESULT`, поле `verdict: "FIXED"` | outer === inner (2d→2d) и/или outer === null (cross) | **фикс 313175 в сборке есть** |
| `P1-RESULT`, поле `verdict: "VULNERABLE"` | outer !== inner: внешний вызов создал новый контекст поверх живого inner | **фикса нет, вектор открыт** → можно `p3` |
| `P1-RESULT`, поле `verdict: "UNKNOWN"` / `"FIXED_PARTIAL"` | геттер словаря не сработал или bitmaprenderer недоступен | смотреть `cases.*.firedKeys`; если `fired=0` — движок не читает опции (или JS-функции нет) |
| `P1-RESULT`, `cases.same_type_2d.firedKeys` | какие члены словаря прочитаны (`desynchronized`, `willReadFrequently`, `alpha`…) | на 14.10 ждём `desynchronized` (alpha в 2d-словаре WebKit закомментирован) |
| `P2-FINGERPRINT`, поле `band` | `17.0..17.3` / `17.4..17.x` / `>=18.x` / `<17.0` | если `>=18.x` — Sony ребейзила движок, и фикс июня-2026 вполне мог попасть; если `17.0..17.3` — база та же, что на 14.10 |
| `P2-FINGERPRINT`, `bits` | побитовая карта 32 API | сравнить с прогоном на 14.10 (публичный p162) |
| `P3-START` … `P3-BEFORE-DEREF` | последний beacon перед чтением freed-контекста | если после `P3-BEFORE-DEREF` нет `P3-AFTER-DEREF`/`P3-SURVIVED`, а страница умерла — crash подтверждён |
| `P3-SURVIVED` | страница дожила | на сборке с фиксом (или если слот не freed) — crash не воспроизведён |

**Решающая строка лога — одна:** `P1-RESULT verdict=VULNERABLE` (вектор открыт) или
`P1-RESULT verdict=FIXED` (закрыт). `p2` нужен, чтобы объяснить причину: `17.0..17.3` при
`FIXED` = «Sony всё-таки влила бэкпорт», `>=18.x` при `FIXED` = «движок ребейзнут».

## Что уже проверено локально (WebKitGTK 2.52.5, фикс есть)

```
p1 -> LOCAL_PAGE_TITLE p1 FIXED
p2 -> LOCAL_PAGE_TITLE p2 >=18.x
p3 -> LOCAL_PAGE_TITLE p3 SURVIVED  (сборка с фиксом, crash не воспроизводится)
```

Полные JSON — в `ps5jb/tools/probe/logs/entry-1422-local-p{1,2,3}.txt`.
Важно: на реальной консоли 14.22 ожидаемое поведение (по датам/базе) — `VULNERABLE`,
если Sony не сделала бэкпорт; см. `recon/webkit-1422-verdict.md` §5.

## Ограничения

- `p1` не трогает свойства освобождённого контекста — поэтому «не роняет». Crash доказывается
  только `p3`, и только как crash/no-crash, не как R/W.
- Если `fetch`/XHR на консоли недоступны, страницы всё равно показывают результат на экране;
  тогда снимайте экран/фотографируйте, лог сервера неполон (будут только `requests.jsonl`
  без тел).
- `bitmaprenderer` может быть отключён на PS5 (тогда `cross_*` = `UNKNOWN`); главный
  дискриминатор — `same_type_2d`, он не зависит от bitmaprenderer.

## Точки расширения (`// EXT` в коде)

- `p1`: после `same_type_2d` — добавить удержание обёрток/GC, новый кейс, доп. поля в отчёт.
- `p2`: добавить проверки новых API для сужения верхней границы.
- `p3`: добавить спрей/несколько удержаний, если понадобится другой сценарий падения.
